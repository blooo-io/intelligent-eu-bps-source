## 1. Executive summary

D5.5 delivers an open-source Billing & Payment Service for INTELLIGENT communities: two-level billing (monthly participant statements plus self-billing legal invoices per consumer→producer pair), Stripe Connect direct charges and payouts, and EWDS Client Gateway integration for market/data-space traffic and the project UI.

**Honest status (2026-11-27).** Package **`v1.2.4`** (INT-471) is the current cut. It freezes INT-470 D5.5 docs drift on top of `v1.2.3` (INT-467 UAT re-cert **64/64 Pass**, INT-447…469).

What is true of the code on `develop`:

- **Stripe test mode** is the default payment path; live keys are selectable per community when enabled (REQ-043).
- **EWDS adapters** are env-selected (`mock` \| `ewds`); **mock is the code default**; deployed Helm values set adapters to `ewds` (A8-live).
- **Five EWDS billing record topics** are published: `billingStatement`, `billingInvoice`, `billingPayment`, `billingPayout`, `billingKycStatus`.
- **External API surface** for the project path is **EWDS only** (INT-455). No public REST `/v1`; no AC-01 reference SPA.
- **In-house PDF** invoices use `pdf-lib` (A6); Stripe Invoicing is removed.
- **Live vs virtual billing mode** is per community; switching to live while periods are open is refused (`409` open-period guard).
- **REQ-061 reminders** are recorded on **AC-06** (`POST /internal/v1/invoices/{id}/reminders`); AC-11 delivers mail (INT-461).
- **EWAG topiccreator** remains externally blocked for live message publish; live CGW UATs stay mock-path labelled where not re-run.

Main deviations from source documents are listed as **DEV-01…DEV-14** in §11.

## 2. Scope and assumptions

### 2.1 In scope for D5.5 V1

- Two-level billing model (statements + pair self-billing invoices), netting, threshold/carry-forward, monthly period by default (REQ-006).
- Stripe Connect + Identity in **test mode** (and live keys only where a community is enabled).
- EWDS Client Gateway adapters for trades, Actor intake, erasure, tariffs, five billing records, and the billing command channel.
- Project UI path via EWDS only (A7); no bilateral Blooo public REST API.
- GDPR export/erasure adapters, retention jobs, no PII in events.
- GitOps deploy to Scaleway Kapsule (`dev` / packaging for `demo`).

### 2.2 Out of D5.5 (deferred)

- Crypto wallets, AMM interface, i-Euro / MiCA (D5.10) — DEV-03.
- DID/VC identity (REQ-062) — DEV-02.
- EV charging billing — DEV-05.
- Grid fee / levy / tax amounts until a DSO tariff is published (structure kept at 0 + mention) — DEV-12.
- Early settlement (REQ-057 deprecated and removed).
- Live EWAG topic grants / production CGW identity — after the report path (INT-306 / INT-307).

### 2.3 Assumption highlights (spec A1–A33 + v6.1 arbitrations)

The requirements table **A1–A33** (`docs/requirements/requirements.md`) remains the numbered source. Positions implemented:

| Id | Position on `develop` |
|---|---|
| **A6 (PDF)** | Billing owns PDFs via `pdf-lib`, stores them, numbers `SB-<producer8>-<seq6>` per producer; Stripe Invoicing removed. Spec A33 (provider invoicing) is invalidated. |
| **A7 (project UI)** | Project UI integrates through EWDS records + command channel only. Public `/v1` reference client **removed** (INT-455). Spec A27 decided (v6.1). |
| **A8-live** | Code default for EWDS adapters is `mock`; every deployed env values file sets MARKET/DATASPACE/ACTOR/ERASURE/TARIFF adapters to `ewds` and enables the command channel. Failures when topics/roles are missing stay alerted — adapters are not silently flipped back to mock. |
| **A9 (IdP)** | **INT-463:** member OIDC RP and member admin are on **R2M** (Blooo-hosted Keycloak); BPS Keycloak is S2S JWT (`module-service`) + ops UI only. DID/VC (REQ-062) is not implemented in V1. Spec A11 remains “to confirm” for the written consortium IdP decision. |

## 6. Security, GDPR, and no PII in events

- **Access control:** EWDS command channel (CGW DID allow-list + `actorId`); internal APIs use `module-service` S2S JWT. Member OIDC sessions stay on R2M (INT-463); participants see only their own data (REQ-010).
- **No personal data** in logs, traces, domain events or EWDS record payloads — identifiers only (Actor UUID, community, trade ids). KYC-sensitive ontology fields are omitted from the Actor EWDS schema.
- **Erasure / export:** DSAR paths via EWDS (project UI) or manager; propagation to PSP; IdP account erase is **delegated to R2M** (`delegated_to_project_ui`, INT-463); legal invoice retention retained; live-mode Connect accounts may report `retained_by_psp` under AML (see release notes).
- **Retention:** configurable personal-cache, invoice-archive and KYC-log periods (`docs/release/RELEASE-NOTES.md`).
- **Secrets:** never committed; OpenBao → External Secrets; Stripe and CGW credentials stay outside Git.
- **Controller / processor roles** and Stripe transfer/residency notes: architecture `05` §4.1; **DPO sign-off pending** (DEV-13).
